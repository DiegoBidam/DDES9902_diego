# 교수 피드백 반영: 공간 안의 UI

## 반영 기준

WebGL은 몰입형 디자인을 보여주는 데스크톱 시제품으로 유지합니다. 화면 고정 HUD, 화면 좌표로 투영한 이름표, OnGUI 메뉴를 제거했습니다. 새 UI는 모두 `RenderMode.WorldSpace` Canvas와 두께 있는 보드 프레임으로 생성합니다. 위치는 입구·옷장·탭·테이블·손님·연습 작업대를 기준으로 정하며 카메라나 플레이어의 자식으로 만들지 않습니다. 시선을 돌리면 표지가 화면 밖으로 벗어납니다. 가독성을 위한 수평 회전은 플레이어의 **월드 위치**만 참고합니다. 머리/카메라 회전을 따라 화면에 붙는 방식은 사용하지 않습니다.

사용하지 않는 튜토리얼의 `Assets/UI/Remaining_Collectibles_UI.prefab`은 기존 보존 조건에 따라 유지했습니다. 메인 바텐더 씬이나 런타임 코드에는 해당 프리팹 참조가 없으며 이번 게임 UI 경로에 사용되지 않습니다.

Quest 실행용 XR 리그나 컨트롤러 SDK를 추가한 것은 아닙니다. 실제 헤드셋 대응과 착용감 검증은 별도 작업입니다.

## 화면별 변경

| 구간 | 공간 속 표현 / 조작 |
| --- | --- |
| 최초 시작 | 최초 시선 앞의 입구 간판. 마우스로 다른 곳을 볼 수 있고 Enter로 시작합니다. |
| 입구·유니폼 | 입구 안내판, 기존 T-SHIRT/APRON 표지, 옷장 옆 착용 체크리스트. 출근하면 착용 상태판이 사라집니다. |
| 맥주 | 탭 위 안내판에 음성 대기·스쿠너/파인트 진행·완료 표시. 실제 서빙 지점에 SERVE HERE 표지. |
| 칵테일 도구·카드 | 도구 옆 공간 이름표, 테이블 위의 기존 그림 카드, 선택한 카드 뒤의 큰 레시피 보드. 영어 재료/제조법 탭과 9개 트라이얼 체크 유지. |
| 제조 연습 | 작업대의 레시피 보드, 물리 타이머, 계량/제출 보드, 물건 위 선택 이름표, 재료 투입 확인 보드. 결과와 재시도/다음 회차/오픈 버튼도 공간 속 보드. |
| 영업 | 카운터의 쉬프트 진행판과 주문표. 손님 앞 응대 선택판과 손님 옆 쉬운 난이도 안내 노트. 제조 시에는 연습 작업대에 주문표 배치. |
| 포인터 | 화면 중앙에 그린 + 대신 실제 표면/보드에 닿는 작은 3D 점. 닿는 곳이 없으면 숨김. |

일반 구간은 표지를 조준해 좌클릭합니다. 레시피나 손님 선택판을 열어도 걷기와 마우스 시점이 유지됩니다. ESC로 닫을 수 있습니다. 연습 작업대는 기존 고정 위치에서 마우스 포인터로 물건/공간 버튼을 선택하고, **오른쪽 마우스를 누른 채 움직여 둘러봅니다**. 스터·쉐이킹은 기존처럼 왼쪽을 누르고 좌우/위아래로 움직입니다. 둘러보는 중에는 스터·쉐이킹 동작과 그 연속 효과음을 진행하지 않습니다. 타이머는 계속 흐릅니다.

공간 버튼은 실제 월드 평면 교점으로 선택합니다. 벽/물체나 더 가까운 보드에 가린 버튼은 클릭할 수 없고, 새 창이 열린 프레임의 클릭은 무시합니다. 한 프레임의 클릭으로 여러 작업을 실행하지 않습니다. 새 프레임은 이동/착용/따르기 Raycast를 막지 않도록 물리 Collider를 제거합니다. UI용 Ray는 별도로 보드 평면을 검사합니다.

## 보존 범위

Assets 변경은 Mac 자동 동기화 대상인 기존 5개 스크립트뿐입니다:

- `Bar intro.cs`: 시작/환영 간판.
- `BarPlayerMovement.cs`: 공간 메뉴를 보는 동안 이동/시점을 막던 조건 제거. ESC의 메뉴 닫기/커서 해제 충돌 방지.
- `BeerGlassPour.cs`: 공통 공간 UI, 맥주/도구/레시피/연습/영업 UI 및 공간 버튼 입력.
- `EntranceGuide.cs`: 입구 자막을 공간 안내판으로 변경.
- `UniformInteraction.cs`: 착용 체크리스트/안내/완료를 공간 안내판으로 변경.

씬, 프리팹, .meta GUID, Inspector 직렬화 필드, 패키지, 튜토리얼 파일과 기존 모델의 위치/회전/크기는 변경하지 않았습니다. 카메라 높이, 잔/도구 배치와 따르기 시간도 그대로입니다. 비어 있던 ShiftClockInteraction을 연결하지 않았습니다. 안내 중 이동 허용·행위 대기, 셔츠→앞치마→출근→맥주, 맥주 2잔 서빙, 음성·배경음·효과음, 레시피의 재료 순서 자유 판정, 15회 왕복, 연습 90/60/45초, 실전 45초와 쉬운 난이도 10명 조건을 유지합니다.

## 수행한 검사와 한계

- C# 구문 트리 검사 통과. 기존 186개 메서드는 그대로이며 제조 판정/음성/효과음/기존 모델 생성과 서빙 로직은 이전 코드와 비교했습니다.
- 기존 직렬화 필드와 큰 내장 음원·그림 문자열 보존 확인. Assets 내 OnGUI / 화면 Canvas / 화면 투영 이름표 없음.
- 실제 코드의 좌표를 읽어 초기 16:9·60도 시야 안에 제조 안내/타이머/계량/확인 보드가 들어오고 10개 재료 이름표를 가리지 않는지 투영 계산으로 확인.
- .NET C# 컴파일러 + 작은 Unity API 대체 코드로 일반 입력 및 WebGL/새 Input System 분기 컴파일 확인.
- 같은 대체 환경에서 114개 공간 입력·UI 상태·레시피 검사 통과. 3개 레시피 × 3회차, 계량·스터·쉐이킹·완료·실패·타임아웃과 주문표/응대창을 포함합니다. `Tools/Validation/SpatialUI/verify.py`로 재실행할 수 있습니다.

이 검사는 Unity 엔진 컴파일이나 Unity 물리/렌더링 검증이 아닙니다. 이 Linux 환경에서는 Unity를 설치·다운로드·실행하지 않았고, 이번 변경의 실제 Mac Unity 컴파일·플레이·Web 빌드는 수행하지 못했습니다. 실제 글꼴 렌더링, 보드 가림, 시야 안 배치와 WebGL 입력은 아래 순서로 확인해야 합니다.

## Mac 확인 순서

1. Play를 중지하고 기존 자동 동기화 터미널에서 최신 커밋의 **적용 확인 완료**를 확인합니다. Unity 컴파일이 끝난 뒤 빨간 오류가 없는지 확인합니다. Inspector에 새 항목을 수동 연결할 필요는 없습니다.
2. 게임 시작 직후 마우스로 시선을 돌립니다. 시작 간판이 화면 중앙을 따라오지 않고 입구에 남아야 합니다. Enter로 시작하고 음성을 들으며 이동할 수 있어야 합니다.
3. 셔츠→앞치마→출근 순서로 진행합니다. 기존 옷 표지와 옷장 옆 체크리스트를 확인하고, 다음 구간에서 착용 상태판이 사라지는지 확인합니다. 안내 중 행위는 기다리되 이동·시점은 유지되어야 합니다.
4. 바에 접근하여 스쿠너→파인트를 집고 E로 따른 뒤 좌클릭으로 서빙합니다. 탭 안내판/서빙 표지/완료 효과음과 바닥 경계 방지를 확인합니다.
5. 칵테일 테이블에서 세 카드를 각각 열고 재료/제조법 탭과 Start to make를 확인합니다. 시선을 돌리거나 걸어도 카드 보드는 테이블에 남아야 합니다. 벽 뒤나 반대편의 보드를 관통 클릭할 수 없어야 합니다.
6. 세 칵테일을 각 3회 제조합니다. 오른쪽 드래그로 둘러보고 왼쪽으로 물건/버튼을 선택합니다. 1회차 전체 안내/90초, 2회차 이름만/60초, 3회차 안내 없는 작업대/45초와 9개 체크를 확인합니다. 3회차에는 계량/제출 안내판도 숨기며 Enter로 제출합니다. 정확한 재료는 순서와 관계없이 성공해야 하며, 잘못된 재료·시간초과는 실패해야 합니다. 스터/쉐이킹은 각각 15회 왕복과 움직임 정지 시 소리 정지를 확인합니다.
7. Open the bar 후 야간 전환 중 둘러보기, 쉬프트 진행판, 손님 응대 3개 선택지, ID 확인, 주취 거절, 맥주 서빙, 칵테일 45초 주문표와 10명 완료를 확인합니다.
8. 통과한 최신 소스로 **새 Web 빌드**를 만듭니다. 이전 성공 빌드를 재압축하는 `--package-existing`은 이번 수정이 들어간 새 빌드를 만드는 명령이 아닙니다. 새 ZIP의 브라우저 시작/마우스 캡처/공간 버튼을 확인한 뒤 Unity Play에 갱신합니다.
