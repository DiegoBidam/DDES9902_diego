# 시점에 반응하는 공간 UI

## 이번 변경

안내를 고정 방향의 판 여러 개로 표시하던 구조를, 사용자 시야에 반응하는 **3D 카드 배치**로 정리했습니다. 모든 카드는 World Space Canvas와 두께 있는 프레임으로 존재하며 카메라의 자식이 아닙니다. Screen Space Canvas나 OnGUI는 사용하지 않습니다.

- 짧은 시선 이동에서는 카드가 원래 공간에 머뭅니다. 기준 방향에서 32도 이상 고개를 돌린 상태가 0.35초 유지되면, 새 시야 옆으로 부드럽게 다시 배치합니다.
- 카드를 조준하거나 읽는 동안에는 회전 재배치를 멈춰 버튼이 커서를 피해 움직이지 않도록 합니다. 0.35m 이내의 작은 위치 변화는 그대로 두되, 계속 걸으면 카드 묶음이 따라와 몸이 카드를 지나치지 않게 합니다. 카드 자체는 사용자의 위치를 향해 읽기 좋은 각도를 취합니다.
- 한 카메라의 모든 카드는 같은 배치 기준을 공유합니다. 주 안내는 왼쪽, 보조 노트·조작은 오른쪽, 레시피·결과는 단독 중앙, 제조 안내는 위쪽, 일시적 완료 메시지는 그 아래에 배치합니다.
- 큰 벽/카운터가 가까울 때나 제조 공간의 작업대·바닥을 향할 때는 카드 묶음의 거리와 크기를 함께 줄여 각도상 간격을 유지합니다. 실제 Unity의 가림·물리·VR 착용감은 별도 확인이 필요합니다.

WebGL은 몰입형 설계를 표현하는 데스크톱 시제품입니다. 이 작업은 Quest/XR 컨트롤러 연동이나 헤드셋 착용감 검증을 포함하지 않습니다.

## 겹침과 정보량 정리

| 상황 | 표시하는 안내 |
| --- | --- |
| 최초 시작 | 시야에 반응하는 시작 카드 하나. Enter로 시작. |
| 입구·착용 | 입구 안내가 재생되면 착용 체크리스트를 숨김. 이후 착용 안내 카드 하나와 실제 옷 표지 사용. |
| 맥주 연습 | 진행 안내 카드 하나. 서빙 표지는 잔이 준비되고 실제 서빙 지점을 조준할 때 표시. |
| 칵테일 카드 읽기 | 레시피 카드만 표시하고 맥주·훈련 요약·도구 이름표 숨김. |
| 오픈·손님 대기 | `BAR OPEN`과 진행 상태를 안내 카드 하나로 통합. 별도 OPEN 판/상태판/주문표 중복 제거. |
| 손님 응대 | 선택 카드 + 필요할 때만 쉬운 난이도 안내 노트. 배경 진행 카드는 숨김. |
| 주문 준비 | 주문과 다음 행동을 한 안내 카드에 표시. |
| 일반 제조 연습 | 안내에 타이머 통합. 계량/제출 카드와 잠깐의 완료 메시지만 추가. |
| 손님 칵테일 제조 | 왼쪽 주문 노트에 45초 타이머 통합, 오른쪽 조작 카드. 완료 메시지는 일시 표시. 별도 레시피 헤더/시계 중복 제거. |
| 3회차 | 간결한 시계와 수행한 행위의 확인만 제공. 정답 용량·다음 단계는 숨김. |
| 영업 종료 | 평가 카드 하나만 표시. 이전 안내·주문·선택·보조 노트 숨김. |

떠 있는 물건 이름표는 조준 중인 물건과 선택한 잔 위주로 제한했습니다. 완료 메시지를 표시하는 동안에는 가까운 이름표를 숨깁니다. 병에 인쇄된 기존 이름, 선택한 잔의 초록 링과 실제 물건의 배치는 유지합니다. 따르는 동안 병 이름표가 다른 표지를 가로질러 움직이지 않습니다.

## 조작과 보존 사항

마우스만 움직여 둘러보고 중앙 3D 포인터로 조준해 좌클릭합니다. 우클릭을 누를 필요는 없습니다. 스터/쉐이킹은 왼쪽을 누르고 좌우/위아래로 움직이며, 버튼을 놓으면 시점 조작이 다시 적용됩니다. 브라우저 포인터 캡처가 풀리면 게임을 한 번 클릭합니다. 이 클릭은 제조 행위로 중복 처리하지 않습니다.

안내 음성 중 이동·시점 허용/행위 대기, 셔츠→앞치마→출근→맥주, 스쿠너→파인트 서빙, 재료 순서 자유 판정, 계량, 15회 왕복, 연습 90/60/45초와 실전 45초를 보존합니다. 이동 경계, 카메라 높이, 기존 병/잔/도구의 위치·크기·따르기 연출과 오디오 데이터는 변경하지 않습니다.

씬·프리팹·.meta GUID·Inspector 필드·패키지·튜토리얼 파일을 변경하지 않았습니다. 사용하지 않는 튜토리얼의 `Remaining_Collectibles_UI.prefab`은 보존하며 메인 씬에 참조되지 않습니다. 수동 Inspector 연결은 필요 없습니다.

변경 런타임 파일은 자동 동기화 대상인 `BeerGlassPour.cs`, `Bar intro.cs`, `UniformInteraction.cs`, `EntranceGuide.cs`입니다. 공통 배치 코드는 기존 `BeerGlassPour.cs` 안에 포함해 새 스크립트 연결이 필요 없습니다.

## 평가 기준

10번째 손님 퇴장 시 실제 결과를 한 번 확정합니다. 점수는 정확한 서빙 + 올바른 ID/주취 거절 비율입니다. A: 90점 이상, B: 80점 이상, C: 70점 이상, D: 70점 미만입니다. **10명 완료 + 70점 이상 + 위험한 판매 선택 0회**이면 클리어입니다. 위험한 판매 선택이 있으면 숫자 점수와 별도로 D등급·미클리어로 처리합니다. 기존 판매 차단 동작은 유지합니다.

## 검사와 Mac 확인 순서

`Tools/Validation/SpatialUI/verify.py`는 이미 설치된 .NET SDK와 작은 Unity API 대체 코드로 일반 입력과 WebGL/Input System 분기를 각각 컴파일·실행합니다. 레시피·음성 데이터 보존, 타이머, 완료·실패·평가, 지연 재배치, 조준 중 이동 방지, 가까운 환경면 대응과 상황별 표시 개수를 검사합니다. 프레임 테두리를 포함한 실제 패널 크기와 배치 슬롯을 코드에서 읽어 30가지 가까운 시점의 투영에서 서로 겹치지 않는지도 계산합니다.

일반 입력 및 WebGL/Input System 분기에서 각각 295개 대체 환경 검사에 통과했습니다.

이것은 Unity 엔진 컴파일·물리·렌더링·브라우저 플레이·헤드셋 테스트가 아닙니다. 여기서는 Unity를 설치·다운로드·실행하지 않았습니다.

1. Play를 중지하고 최신 커밋의 자동 동기화 `적용 확인 완료`를 확인합니다.
2. 시작/입구/착용을 진행하며 동시에 두 개의 큰 안내 카드가 겹치지 않는지 확인합니다.
3. 바를 오픈하고 시선을 크게 돌린 뒤 잠시 기다립니다. 안내가 새 시야 옆으로 이동해야 합니다. 카드를 조준하면 버튼 위치가 안정돼야 합니다.
4. 손님 선택창·ID 안내·주문 준비·제조 화면을 전환하며 이전 카드가 숨겨지는지 확인합니다.
5. 일반 연습의 안내/타이머 통합, 손님 제조의 주문 노트/45초 통합, 3회차의 선택 링과 완료 메시지를 확인합니다.
6. 손님 10명 종료 후 평가표 하나만 보이는지 확인합니다.
7. 통과한 최신 소스로 새 Web 빌드를 만들어 브라우저에서 확인한 뒤 업로드합니다. 기존 ZIP 재압축에는 새 코드가 포함되지 않습니다.
